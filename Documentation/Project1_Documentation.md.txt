5. PHASE 0: DIRTY DATA AUDIT
================================================================================

The audit phase follows the DecodeLabs principle: "Before you finish, you must
prove there are zero duplicate IDs and zero incorrectly formatted dates."

This phase systematically scans the dataset for 8 categories of data quality
issues. Issues found are flagged for correction; issues not found are
documented as "clean — no modification required."

--------------------------------------------------------------------------------
5.1 HEADER ROW VERIFICATION
--------------------------------------------------------------------------------

ISSUE: Excel files sometimes import with the header row duplicated as data.

CHECK PERFORMED:
  Examined df.iloc[0] (first data row) to verify it contains actual order data,
  not repeated column names.

RESULT: ✅ CLEAN — NO MODIFICATION REQUIRED
  First row contains valid order record (ORD200000, 2023-01-04, C72649, ...).
  No header duplication detected.

--------------------------------------------------------------------------------
5.2 DUPLICATE DETECTION (OrderID)
--------------------------------------------------------------------------------

ISSUE: Duplicate OrderIDs inflate transaction counts and break uniqueness.

CHECK PERFORMED:
  df.duplicated(subset=['OrderID'], keep=False)
  Equivalent SQL: GROUP BY OrderID HAVING COUNT(*) > 1

RESULT: ✅ CLEAN — NO MODIFICATION REQUIRED
  Total duplicate OrderID rows: 0
  All 1,200 OrderIDs are unique.

--------------------------------------------------------------------------------
5.3 MISSING VALUES ANALYSIS
--------------------------------------------------------------------------------

ISSUE: Null values break aggregations, filters, and machine learning pipelines.

CHECK PERFORMED:
  df.isnull().sum() — column-wise null count

RESULT: ⚠️ ISSUE FOUND — REQUIRES MODIFICATION
  CouponCode: 309 missing (25.8% of dataset)
  All other columns: 0 missing

  The 25.8% missing rate is significant. Per DecodeLabs Phase 1 guidance:
  "Handle the Gaps. Don't just delete." Listwise deletion would remove 309
  rows (25.8% data loss), reducing statistical power and skewing analysis.

  RESOLUTION: See Phase 1 — Strategic Imputation (CR001)

--------------------------------------------------------------------------------
5.4 BLANK/EMPTY VALUES CHECK
--------------------------------------------------------------------------------

ISSUE: Empty strings ('', '  ') behave differently from nulls but cause
identical analytical problems.

CHECK PERFORMED:
  For each object column: (df[col].astype(str).str.strip() == '').sum()

RESULT: ✅ CLEAN — NO MODIFICATION REQUIRED
  No blank or whitespace-only values detected in any column.

--------------------------------------------------------------------------------
5.5 DATE FORMAT ASSESSMENT
--------------------------------------------------------------------------------

ISSUE: Dates in inconsistent formats (MM/DD/YYYY, DD-MM-YY, Excel serial
numbers) break sorting, filtering, and time-series analysis.

CHECK PERFORMED:
  df['Date'].dtype — verified datetime64[ns] type
  Sample inspection of first 5 values

RESULT: ⚠️ PARTIAL ISSUE — REQUIRES MODIFICATION
  Dates are already datetime objects (not Excel serial numbers), but stored
  as datetime64[ns] which includes time component (00:00:00).

  DecodeLabs standard: ISO 8601 Dates (YYYY-MM-DD) as string format.

  RESOLUTION: See Phase 3 — Date Standardization (CR003)

--------------------------------------------------------------------------------
5.6 NUMERIC PRECISION AUDIT
--------------------------------------------------------------------------------

ISSUE: Floating-point arithmetic produces artifacts like 769.3799999999999
instead of 769.38, corrupting financial reports.

CHECK PERFORMED:
  Regex scan for values with >2 decimal places: r'\.\d{3,}'

RESULT: ⚠️ ISSUE FOUND — REQUIRES MODIFICATION
  TotalPrice values with >2 decimals: 29
  Examples: 769.3799999999999, 635.9000000000001, 440.1899999999999

  Root cause: IEEE 754 floating-point representation in Excel/Python.

  RESOLUTION: See Phase 3 — Numeric Precision (CR002)

--------------------------------------------------------------------------------
5.7 TEXT STANDARDIZATION REVIEW
--------------------------------------------------------------------------------

ISSUE: Inconsistent text casing ('mumbai' vs 'MUMBAI'), extra whitespace,
and mixed formats break grouping and filtering.

CHECK PERFORMED:
  Unique value inspection for Product, PaymentMethod, OrderStatus,
  ReferralSource, and ShippingAddress columns.

RESULT: ✅ CLEAN — NO MODIFICATION REQUIRED
  Product:     ['Chair', 'Desk', 'Laptop', 'Monitor', 'Phone', 'Printer', 'Tablet']
  Payment:     ['Cash', 'Credit Card', 'Debit Card', 'Gift Card', 'Online']
  OrderStatus: ['Cancelled', 'Delivered', 'Pending', 'Returned', 'Shipped']
  Referral:    ['Email', 'Facebook', 'Google', 'Instagram', 'Referral']

  All categorical fields are already in Proper Case with no whitespace issues.
  No Bangalore/Bengaluru/BLR-style inconsistencies detected.

--------------------------------------------------------------------------------
5.8 COMPUTED FIELD VALIDATION
--------------------------------------------------------------------------------

ISSUE: Computed columns (TotalPrice = Quantity × UnitPrice) may contain
errors from source system bugs or manual entry mistakes.

CHECK PERFORMED:
  ComputedTotal = Quantity × UnitPrice
  PriceDiff = |TotalPrice - ComputedTotal|
  Flag rows where PriceDiff > $0.01

RESULT: ✅ CLEAN — NO MODIFICATION REQUIRED
  Mismatches found: 0
  All 1,200 rows validate within $0.01 tolerance.
  The source system correctly computes TotalPrice from Quantity and UnitPrice.

6. PHASE 1: STRATEGIC IMPUTATION
================================================================================

CHANGE ID: CR001
ISSUE: CouponCode — 309 missing values (25.8%)

STRATEGY SELECTION:
┌─────────────────┬──────────────────────────────────────────────────────────┐
│ Method          │ Why Rejected/Selected                                    │
├─────────────────┼──────────────────────────────────────────────────────────┤
│ Listwise Delete │ ❌ REJECTED — Removes 309 rows (25.8% data loss).        │
│                 │     Violates DecodeLabs warning: "reduces statistical   │
│                 │     power."                                              │
├─────────────────┼──────────────────────────────────────────────────────────┤
│ Mean Imputation │ ❌ REJECTED — CouponCode is categorical (text), not      │
│                 │     numeric. Mean is mathematically invalid.             │
├─────────────────┼──────────────────────────────────────────────────────────┤
│ Mode Imputation │ ❌ REJECTED — While mode exists ('SAVE10'), forcing    │
│                 │     309 customers to have a coupon distorts business   │
│                 │     reality. Not all customers use coupons.              │
├─────────────────┼──────────────────────────────────────────────────────────┤
│ "NONE" Flag     │ ✅ SELECTED — Business-meaningful. Explicitly marks    │
│                 │     "no coupon used." Preserves all 1,200 records.       │
│                 │     Enables accurate "coupon vs. no-coupon" analysis.  │
└─────────────────┴──────────────────────────────────────────────────────────┘

CODE EXECUTED:
  df['CouponCode'] = df['CouponCode'].fillna('NONE')

IMPACT:
  Before: 309 missing (25.8%)
  After:  0 missing (0%)
  Data loss: 0 rows (0%)
  Records preserved: 1,200

This phase applies the "Speak One Language" principle from the DecodeLabs

--------------------------------------------------------------------------------
8.1 DATE STANDARDIZATION (CR003)
--------------------------------------------------------------------------------

STANDARD: ISO 8601 (YYYY-MM-DD)

ISSUE: Dates stored as datetime64[ns] objects include time component
(2023-01-04 00:00:00) and may cause format inconsistencies in exports.

CODE EXECUTED:
  df['Date'] = pd.to_datetime(df['Date']).dt.strftime('%Y-%m-%d')

VALIDATION:
  Regex check: ^\d{4}-\d{2}-\d{2}$
  Invalid date formats found: 0

BEFORE/AFTER:
  Before: 2023-01-04 00:00:00 (datetime64[ns])
  After:  2023-01-04 (string, ISO 8601)

--------------------------------------------------------------------------------
8.2 NUMERIC PRECISION (CR002)
--------------------------------------------------------------------------------

STANDARD: 2 decimal places for all monetary fields

ISSUE: 29 TotalPrice values contain floating-point artifacts from IEEE 754
binary representation (e.g., 769.3799999999999 instead of 769.38).

CODE EXECUTED:
  df['UnitPrice'] = df['UnitPrice'].round(2)
  df['TotalPrice'] = df['TotalPrice'].round(2)

VALIDATION:
  Values with >2 decimals after fix: 0

BEFORE/AFTER:
  Before: 769.3799999999999
  After:  769.38

BUSINESS IMPACT:
  Financial reports now sum correctly. No more $0.01 discrepancies in
  reconciliation. Customer invoices display clean pricing.

11. KEY LEARNINGS & BEST PRACTICES
================================================================================

1. AUDIT BEFORE CLEANING
   Never modify data before understanding what's dirty. The 8-issue scan
   revealed that 5 issues were already clean — saving time and preventing
   unnecessary transformations.

2. PRESERVE STATISTICAL POWER
   The DecodeLabs warning about listwise deletion is critical. Deleting 309
   rows (25.8%) would have destroyed sample size and biased results.
   Strategic imputation preserves data integrity.

3. CHOOSE CONTEXT-APPROPRIATE IMPUTATION
   Mean/median/mode are not universal solutions. For categorical fields like
   CouponCode, a business-meaningful flag ('NONE') is more accurate than
   statistical imputation.

4. DOCUMENT EVERYTHING
   The Change Log is not bureaucracy — it's accountability. Stakeholders,
   auditors, and future-you need to know what changed and why.

5. REPRODUCIBLE WORKFLOWS
   Python scripts > Excel manual steps. Scripts can be re-run, version-
   controlled, and peer-reviewed. This is the "Pro Move" per DecodeLabs.
